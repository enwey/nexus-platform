# 后台模块生产级交付标准

## 1. 目标

本标准用于约束 `ops-portal`、`dev-portal`、`backend` 的所有后台模块开发流程。

从本文件生效开始，任何后台模块进入开发前，必须先完成以下 10 项设计产出：

1. 模块 PRD
2. 数据对象设计
3. 状态流转设计
4. 权限设计
5. 接口设计
6. 数据库设计
7. 异常场景设计
8. 操作日志设计
9. 测试用例设计
10. 验收标准

## 2. 适用范围

- 运营后台模块
- 开发者后台模块
- 后端服务
- 管理类开放接口
- 后台上传、审核、发布、推荐、配置、风控、日志相关能力

## 3. 强制门禁

以下规则为强制规则，不允许以“先做 Demo”“先把页面跑通”为理由跳过：

- 不允许只实现表面 UI
- 不允许省略后端校验
- 不允许只靠前端控制权限
- 不允许非法状态流转
- 不允许敏感操作无日志
- 不允许危险操作无二次确认
- 不允许开发者访问其他开发者数据
- 不允许接口缺少参数校验
- 不允许上传文件缺少格式和大小校验
- 不允许重复提交导致重复数据
- 不允许空状态、错误状态、加载状态缺失

## 4. 设计与开发顺序

每个模块必须按以下顺序推进：

1. 输出模块设计文档
2. 完成接口与数据模型审查
3. 完成状态机与权限矩阵审查
4. 完成数据库变更方案
5. 完成异常与审计方案
6. 完成测试用例
7. 再进入编码
8. 编码完成后执行模块自查
9. 自查问题清零后才允许进入下个模块

## 5. 模块文档模板

每个模块文档必须固定包含以下章节：

### 5.1 模块 PRD

- 模块目标
- 用户角色
- 业务价值
- 核心页面 / 核心动作
- 非目标范围

### 5.2 数据对象设计

- 核心实体
- 字段定义
- 字段来源
- 是否可编辑
- 是否审计
- 是否敏感

### 5.3 状态流转设计

- 状态枚举
- 允许流转
- 禁止流转
- 触发动作
- 流转后副作用

### 5.4 权限设计

- 角色
- 菜单权限
- 数据权限
- 操作权限
- 越权校验规则

### 5.5 接口设计

- 接口路径
- 请求参数
- 参数校验
- 幂等策略
- 返回结构
- 错误码

### 5.6 数据库设计

- 表结构
- 索引
- 唯一约束
- 软删 / 硬删策略
- 审计字段

### 5.7 异常场景设计

- 参数非法
- 状态非法
- 越权访问
- 并发冲突
- 重复提交
- 外部依赖失败
- 空数据场景

### 5.8 操作日志设计

- 记录什么
- 谁操作
- 操作前后差异
- 请求来源
- 风险等级

### 5.9 测试用例设计

- 正常流
- 越权流
- 非法状态流
- 并发流
- 空数据流
- 错误恢复流

### 5.10 验收标准

- 业务可用
- 权限安全
- 状态正确
- 日志完整
- 异常可见
- 前后端一致

## 6. 模块开发自查

每个模块开发完成后，必须逐项回答并修复问题：

1. 这个模块是否能真实上线使用？
2. 是否有权限漏洞？
3. 是否有数据越权风险？
4. 是否有状态流转漏洞？
5. 是否有重复提交问题？
6. 是否有异常场景未处理？
7. 是否有操作日志缺失？
8. 是否有测试用例缺失？
9. 是否只是 Demo 级实现？

## 7. 交付物要求

每个模块至少应产出：

- 1 份模块设计文档
- 对应后端接口与校验代码
- 对应数据库变更脚本
- 对应操作日志方案
- 对应测试清单
- 对应前端页面的空态 / 错态 / 加载态

## 8. 当前执行策略

当前项目将先对 P0 核心模块补齐设计包，再继续实现。

P0 优先级：

- 运营后台审核中心
- 运营后台游戏治理中心
- 运营后台推荐运营中心
- 开发者后台游戏与版本发布中心
- 开发者后台账号与团队中心

# Token Lean Dev

用最小可行上下文完成工作。

## 規則

1. 先搜尋，再讀檔；優先用 `rg`、`rg --files`、`git status --short`。
2. 只讀必要片段；優先函式、符號、命中行附近，不預設讀整檔。
3. 摘要只保留一份；不要重複讀同樣內容。
4. 修改限制在最小檔案集合；避免順手擴 scope。
5. 驗證跑最小必要檢查；優先 targeted tests。
6. 回報只講發現、修改、驗證、風險；保持簡短。
7. Android 或 iOS 任務預設不做編譯、打包、安裝，也不主動跑完整測試；只有使用者明確要求時才執行。

## 流程

1. 找候選檔案。
2. 讀關鍵區塊。
3. 形成短假設。
4. 做最小修改。
5. 做最小驗證。

## 避免

- 不主動讀 `node_modules`、產物檔、lockfile、大型快照。
- 不因為「可能有關」就多讀相鄰檔案。
- 不在根因未明時做大改。

## 內部短句

- 「先縮面，不擴 scope。」
- 「只需要一條 call path、一個設定來源、一個驗證步驟。」
- 「先證明，再擴大。」
